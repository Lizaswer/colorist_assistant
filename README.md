# ИИ-ассистент колориста

Помогает колористу рассчитать или проверить формулу окрашивания волос и объясняет
каждое решение. Формулу считают правила колористики, языковая модель (необязательно) только объясняет.

> Статус: первая версия, сквозной сценарий работает. Правила в `colorist/rules/knowledge.py`
> черновые и помечены `TODO(колористы)`, эталонные случаи пока синтетические.

Документация проекта — в [docs/](docs/README.md): проблема, концепция, критерии,
решения, риски, журнал работы с ИИ.

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

uvicorn colorist.api.main:app --reload
```

Открой http://127.0.0.1:8000/ — анкета, формула с объяснением и проверка своей формулы.
API с формами для отладки — http://127.0.0.1:8000/docs.

## Другие команды

```bash
pytest                           # все тесты, включая эталонные случаи
python scripts/evaluate.py       # прогон случаев → docs/evaluation/report.md
python demo.py                   # расчёт и проверка в консоли, без сервера
python scripts/benchmark.py      # замер времени по этапам (нужен ключ API)
```

## Языковая модель (необязательно)

По умолчанию объяснение собирается по шаблону. Чтобы его пересказывала модель, задай ключ в
переменных окружения (в файлы ключ не записывать):

```bash
export OPENAI_API_KEY=...        # или ANTHROPIC_API_KEY
export COLORIST_USE_LLM=1
export COLORIST_LLM_BASE_URL=...   # необязательно: другой адрес API, например https://api.aitunnel.ru
export COLORIST_LLM_MODEL=...      # необязательно
```

Windows cmd: `set OPENAI_API_KEY=...`. Если модель недоступна или изменила цифры, возвращается шаблон.
Ответы кэшируются в памяти; отключить: `COLORIST_LLM_CACHE=0`.

```
├── tests/                  # pytest

```

## Как устроена объяснимость

Каждый шаг расчёта и каждый риск содержит `rule_id`. Полный список правил —
словарь `RULES` в `knowledge.py`. Тест `test_every_step_points_to_a_known_rule`
следит, чтобы система не выдавала решений без правила.

## Как добавить эталонный случай

1. Скопируй `data/cases/00-example.json` в новый файл, например `10-ak.json`.
2. Заполни `hair` и `target` по карточке случая из интервью, поставь `"verified": true`.
3. В `expected` — формулу, которую мастер считает правильной.
4. Если есть неудачная формула — положи её в `master_formula`,
   а в `expected_risk_ids` — риски, которые система должна найти.
5. Если система заведомо не справится — опиши причину в `known_gap`.
6. Запусти `python scripts/evaluate.py` и `pytest`.

Расхождение на реальном случае — это не поломка, а находка: правило
нужно уточнить вместе с колористом.

## Рамки MVP

- один бренд;
- тон в тон и затемнение на 1–2 тона, без осветления;
- ввод через анкету, без фото;
- ассистент помогает мастеру, но не заменяет его; тест на аллергию обязателен.
