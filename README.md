# ИИ-ассистент колориста

Помогает колористу рассчитать или проверить формулу окрашивания волос и объясняет
каждое решение. Формулу считают правила колористики, языковая модель (позже) только объясняет.

> Статус: первая версия, сквозной сценарий работает. Правила в `colorist/rules/knowledge.py`
> черновые и помечены `TODO(колористы)`, эталонные случаи пока синтетические.

Документация проекта — в [docs/](docs/README.md): проблема, концепция, критерии,
решения, риски, журнал работы с ИИ. Формат и просмотр логов описаны в
[docs/LOGGING.md](docs/LOGGING.md), история исправлений — в
[docs/CHANGELOG.md](docs/CHANGELOG.md).
Рекомендации по ключам и публикации API — в [docs/SECURITY.md](docs/SECURITY.md).

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

uvicorn colorist.api.main:app --reload
```

Открой http://127.0.0.1:8000/ — анкета, формула с объяснением и проверка своей формулы.
API с формами для отладки — http://127.0.0.1:8000/docs.

## Другие команды

```bash
pytest                           # все тесты, включая эталонные случаи
python scripts/evaluate.py       # прогон случаев → docs/evaluation/report.md
python demo.py                   # расчёт и проверка в консоли, без сервера
python demo_wella.py             # расчёт по линиям Wella в консоли
```

Логи всех расчётов, проверок и запросов пишутся в Markdown-файл `logs/colorist.md`.

## Как добавить бренд или линию

Расчёт не содержит ветвления «if бренд == Wella». Все отличия бренда описаны
данными в `BrandProfile` (`colorist/brands/base.py`): палитра уровней и тонов,
коды направлений, натуральная база, доступные оксиды и правила их выбора,
соотношение смеси, время выдержки, границы затемнения.

Чтобы добавить линию:

1. Опишите новый `BrandProfile` (см. `colorist/brands/wella.py`).
2. Зарегистрируйте его в `BRANDS` (`colorist/brands/__init__.py`).
3. Добавьте эталонные кейсы в `data/cases/` с полями `brand` и `line`.
4. Запустите `pytest` и `python scripts/evaluate.py`.

Линия автоматически появляется в UI (загружается из `GET /brands`) и в API.

## Нотация оттенков

Движок понимает обе нотации: слэш (`7/1`) и десятичную (`7.43`, `6.112`).
Многозначный тон считается валидным, если его первая цифра — известное
направление линии (для `6.112` это `1`).

## Рамки MVP

- бренды: Wella (Koleston Perfect, Illumina Color, Color Touch) и универсальный профиль;
- тон в тон и затемнение до 2 уровней от корней, без осветления;
- одна формула на голову (без раздельного расчёта «корни / длина»);
- без корректоров и спецнюансов в расчёте;
- ввод через анкету, без фото;
- ассистент помогает мастеру, но не заменяет его; тест на аллергию обязателен.

Реальные кейсы колориста (`data/cases/11..13-*`) зафиксированы как эталон и
помечены `SKIP`: они требуют раздельных формул по зонам, корректоров в
сантиметрах и осветления корней. Список недостающих правил — в `known_gap`
каждого кейса и в [docs/evaluation/report.md](docs/evaluation/report.md).

## Как устроена объяснимость

Каждый шаг расчёта и каждый риск содержит `rule_id`. Полный список правил —
словарь `RULES` в `knowledge.py`. Тест `test_every_step_points_to_a_known_rule`
следит, чтобы система не выдавала решений без правила.

## Как добавить эталонный случай

1. Скопируй `data/cases/00-example.json` в новый файл, например `14-ak.json`.
2. Заполни `hair` и `target` по карточке случая из интервью, поставь `"verified": true`.
3. Укажи `"brand"` и `"line"` (например, `"wella"` и `"koleston_perfect"`).
   Без этих полей используется бренд по умолчанию — Wella Koleston Perfect.
4. В `expected` — формулу, которую мастер считает правильной.
5. Если есть неудачная формула — положи её в `master_formula`,
   а в `expected_risk_ids` — риски, которые система должна найти.
6. Если система заведомо не справится — опиши причину в `known_gap`.
   Кейс без `expected` получает в отчёте статус `SKIP`, а не `FAIL`.
7. Запусти `python scripts/evaluate.py` и `pytest`.

Расхождение на реальном случае — это не поломка, а находка: правило
нужно уточнить вместе с колористом.

Реальные кейсы колориста (`data/cases/11..13-*`) хранят решение в блоке
`colorist_solution` с разбивкой по зонам (`корни` / `длина`), корректорами в
сантиметрах и процентом оксида для каждой зоны. Это целевой формат расчёта;
пока движок его не воспроизводит, поэтому такие кейсы помечаются `SKIP`,
а недостающие правила перечислены в `known_gap`.
