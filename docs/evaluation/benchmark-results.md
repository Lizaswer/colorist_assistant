# Результаты benchmark: ДО и ПОСЛЕ оптимизации

## Проект

Colorist Assistant — приложение для колориста с rule-based калькулятором и отдельным ИИ-ассистентом, который использует внешний OpenAI API.

## Pipeline

`input → preprocessing → model/API → postprocessing → result`

### Bottleneck

**model/API — 8.4392 s (100% pipeline в данном измерении).**

## Оптимизация

После нахождения bottleneck была выбрана одна оптимизация: **caching**.

Цель: не выполнять новый LLM-вызов для повторного одинакового запроса.

## Сравнение

**До:** 8.4392 s

**После:** 2.2640 s

Снижение среднего времени выбранного повторяющегося сценария:

**≈ 73.2%**

Ускорение:

**≈ 3.7×**

Количество обращений к LLM:

`3 API calls → 1 API call + 2 CACHE HIT`

## Важное ограничение

Caching не ускоряет новый уникальный вопрос. Для нового запроса внешний API по-прежнему вызывается.

Поэтому результат **2.2640 s** относится именно к сценарию:

`1 новый запрос + 2 повторных запроса из cache`.
