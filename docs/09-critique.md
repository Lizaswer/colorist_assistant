# Критика в отдельном чате

Задание пары: попросить ИИ **без истории разработки** найти риски и слабые места,
а затем разобрать каждое замечание самой.

## Как сделано

1. Открыт новый чат без истории реализации (этот файл не опирается на код).
2. В основу критики положена концепция: проблема, пользователь, гибрид правил + LLM,
   рамки MVP, методика оценки, конкуренты.
3. Ниже — замечания рецензента и выводы команды.

## Промпт

```
Ты — скептичный рецензент: опытный колорист и одновременно инженер ML-систем.
Тебе прислали концепцию учебного проекта «ИИ-ассистент колориста» (во вложении).

Найди причины, по которым проект может не сработать. Не хвали и не предлагай
новые функции. Разбери по отдельности:
1. Реальна ли боль и готовы ли начинающие колористы этим пользоваться.
2. Можно ли вообще формализовать расчёт формулы правилами, что правила не поймают.
3. Слабые места методики оценки: 20–30 случаев, слепая оценка, сравнение с ColorClick.
4. Чем проект на самом деле отличается от конкурентов и не преувеличена ли новизна.
5. Риски для клиента и ответственность.

Для каждого замечания: суть в одном предложении, насколько серьёзно
(высоко / средне / низко) и как это проверить за 1–2 недели.
Если данных для вывода не хватает — так и скажи.
```

## Замечания рецензента (отдельный чат)

| № | Замечание | Серьёзность | Как проверить за 1–2 недели |
| --- | --- | --- | --- |
| К1 | Боль реальна (переделки стоят денег), но начинающий в смене может не заполнять анкету: нужен готовый ответ за 30 секунд, а не второй учебник. | высоко | 5 интервью: спрашивать, в какой момент считают формулу и сколько готовы тратить времени на ввод |
| К2 | ColorClick уже закрывает «посчитай за меня»; без привычки объяснять шаги новичок может не увидеть ценности объяснимости. | средне | На интервью показать макет с ID правил и спросить: это плюс или шум |
| К3 | Формализация правилами ловит только то, что есть в анкете; скрытые переменные (металлы, остаток красителя, неравномерная пористость, качество диагностики уровня) дают «уверенно неверную» формулу. | высоко | Собрать 5 неудачных реальных случаев и пометить, каких полей не хватило |
| К4 | Правила без выбранного бренда — это чужая нумерация нюансов; мастер ESTEL и мастер Schwarzkopf получат числа, которые нельзя набрать в тюбике. | высоко | На первом интервью зафиксировать бренд и сверить таблицу оксида/нюансов с картой бренда |
| К5 | Одна формула на голову не описывает типичную работу корни/длина; без этого мастер не доверит расчёт. | высоко | Спросить колористов, в какой доле визитов длина считается отдельно |
| К6 | 20–30 случаев не покрывают комбинаторику уровней × седина × история; метрика 80% на такой выборке легко завышается. | высоко | Не обещать 80% до реальных случаев; заранее описать стратификацию (седина, хна, корни≠длина) |
| К7 | Синтетические эталоны, составленные по тем же правилам, что считает система, проверяют код, а не колористику. | высоко | Пометить `verified: false`; точность считать только на случаях мастера |
| К8 | Слепая оценка знакомыми колористами смещена: они узнают «наш» стиль объяснения или жалеют учебный проект. | средне | Внешний оценщик и шкала без указания источника; не показывать шаги правил при оценке формулы |
| К9 | Сравнение с ColorClick может сорваться: нет API, платная подписка, другой набор полей анкеты. | средне | За неделю проверить, можно ли руками прогнать 5 одинаковых анкет в ColorClick |
| К10 | Новизна объяснимости преувеличена: это UI поверх правил, конкурент может добавить текст; отличимый кусок — проверка формулы мастера и измеримый отчёт. | средне | На интервью спросить, чего не хватает в ColorClick: объяснения, проверки своей формулы, цены |
| К11 | Отказ от осветления снижает риск, но неверное затемнение и перекрытие седины тоже портят волосы; дисклеймер не снимает претензию клиента. | высоко | Юридически не позиционировать как замену мастеру; в интерфейсе оставить обязанность теста на аллергию |
| К12 | Данных, пользуются ли новички ИИ-расчётом ежедневно, в концепции нет. | — | Это пробел, не вывод: закрывается интервью |

Рецензент не предлагал новых функций и не хвалил идею. Вывод: учебный сквозной сценарий возможен, продукт «как у ColorClick, но правильнее» — нет, пока нет бренда, реальных случаев и честной оценки.

## Замечания и выводы команды

| Замечание | Серьёзность | Решение: принять / проверить / отклонить | Почему |
| --- | --- | --- | --- |
| К1. Анкета может не вписаться в смену | высоко | проверить | На интервью спросить про время ввода; для пары оставляем анкету как есть |
| К2. Объяснимость может быть шумом | средне | проверить | ID правил оставляем: они нужны для учёбы и тестов; ценность для мастера — вопрос интервью |
| К3. Скрытые переменные | высоко | принять | Уже в [06-risks.md](06-risks.md); не обещаем полноту диагностики |
| К4. Нет бренда — чужие нюансы | высоко | принять | Правила помечены `TODO(колористы)`; сверка бренда — следующий шаг после пары |
| К5. Корни и длина | высоко | принять | Зафиксировано случаем 04; в план — отдельная формула для длины |
| К6. 20–30 случаев мало | высоко | принять | 80% — цель после реальных случаев, не текущий результат |
| К7. Синтетика проверяет код, не истину | высоко | принять | В отчёте явная пометка; `verified: 0` |
| К8. Смещение оценщиков | средне | принять | В методике: слепая оценка без указания источника; знакомых не считать единственными судьями |
| К9. ColorClick может быть недоступен | средне | проверить | Попробовать 5 анкет руками после пары |
| К10. Новизна уже сформулирована скромно | средне | отклонить как «преувеличение в доках» | В концепции новизна — объяснимость, точность и проверка формулы, не «первый ИИ». Усилить акцент на checker |
| К11. Ответственность | высоко | принять | MVP без осветления и с дисклеймером оставляем; формула — совет мастеру |
| К12. Нет данных об использовании | — | проверить | Закрывается гайдом интервью |
