## 10.10.2026 — замер скорости, LLM в объяснениях, кэш

| Мой запрос | Что предложил ИИ | Моё решение |
| --- | --- | --- |
| Найти медленный участок проекта (задание пары) | Сначала измерить этапы. Замер на чистом Python показал: все этапы, кроме импорта (около 20 мс), занимают доли миллисекунды, а LLM в проекте нет — значит, bottleneck пока отсутствует | Согласилась подключить LLM в объяснение: иначе измерять нечего |
| Подключить языковую модель | `llm.py` на стандартной библиотеке (Anthropic и OpenAI-совместимые API); в `explainer.py` шаблон остаётся по умолчанию, LLM включается `COLORIST_USE_LLM=1`, при сбое — откат на шаблон; проверка, что модель не добавила и не изменила цифры | Использовала ключ AITunnel, модель `~openai/gpt-mini-latest` |
| Замер «до» | `scripts/benchmark.py`: input → preprocessing → rules → llm → postprocessing | Запустила, результат в `docs/evaluation/perf-before.json` |
| Варианты оптимизации после замера | Кэш ответов, более короткий ответ (`max_tokens`), другая модель, streaming; batching и параллельность не подходят — в запросе один вызов модели | Принят кэш: правила детерминированы, одинаковый ввод даёт одинаковый запрос |
| Замер «после» | `--cache`: промах и попадание кэша считаются отдельно, прогноз по доле повторов помечен как расчёт | Запустила, результат в `docs/evaluation/perf-after.json` |

Что узнала:

- До: 2.50 сек на запрос, из них вызов модели 2.4985 сек (около 100%). Остальные этапы вместе — меньше миллисекунды.
- После: повторный запрос 0.0006 сек вместо 2.7. Первый запрос не ускоряется: промах 2.72 сек.
- Разница между 2.50 и 2.72 на промахе — в пределах шума: 6 замеров, p95 пересекаются (3.4 и 3.0). Вывода «кэш замедлил» или «не замедлил» отсюда не сделать.
- Общая медиана при `--runs 3` с кэшем обманчива (2 из 3 запросов — повторы), поэтому промах и попадание считаются раздельно.
- Прогноз «30/50/80% повторов» — арифметика, не измерение. Реальную долю повторов в салоне пока не знаю.
- Ответ модели в среднем 848 символов. Возможно, время вызова зависит от длины ответа — это гипотеза для следующей оптимизации, не проверена.
- Искажённых цифр не найдено ни в одном из 24 реальных ответов модели (18 без кэша и 6 промахов кэша; 12 попаданий — повторы из кэша).

Что ИИ сделал неверно:

- Клиент `llm.py` скрывал текст HTTP-ошибки, поэтому 429 нельзя было диагностировать. Исправлено: ошибка теперь содержит ответ провайдера. Причиной оказался нулевой баланс (`credit_balance_exhausted`).
- Модель `gpt-4o-mini` по умолчанию не разрешена для ключа AITunnel (403). ИИ не знал список моделей; подставила разрешённую из текста ошибки.
- ИИ не мог вызвать настоящую модель из своей среды: код проверен на локальном mock-сервере, а реальные замеры сделала я.
- Тесты кэша ИИ прогонял вручную без pytest.

Проверка на моём компьютере (10.10.2026, Windows, Python 3.13): `python -m pytest` — 32 passed, 3 xfailed. Было 24 passed, 3 xfailed; добавлено 8 тестов объяснения и кэша.

## Что ИИ сделал плохо или я поправила

- ИИ не может проверить правила колористики — значения взяты «из общих знаний» и помечены
  как черновые. Проверять буду с колористами.
- Все тестовые случаи составил ИИ, поэтому совпадения в отчёте ничего не говорят о точности.
- ИИ не мог сам измерить скорость реальной модели: замеры сделаны на моём компьютере, выводы про кэш — по моим цифрам.
